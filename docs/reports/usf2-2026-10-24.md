# US-F2-001 live run and the F2a budgets — 2026-10-24

T-F2-12. F2a's exit criterion, the reference scenario of PRD F2 §9, is run against a real daemon.
It also measures F2a's three budgets (PRD F2 §7, NFR-F2-01…03). Both are driven by
`e2e/usf2/run.sh`, which runs `cmd/umbrald/usf2_live_test.go` and `usf2_nfr_live_test.go` (tag
`live`).

## Setup

- **Repository:** made by `e2e/usf2/fixture.sh` and committed on `main`. It is a Go module with:
  - a failing test: `Max` keeps the smallest value;
  - a stale README: it names `Sum`, which does not exist, and omits `Max` and `Report`;
  - `Mean`, called from `report.go`.
- **Threads:** three threads in one workspace, each created with `worktree: true` and sent its task
  at the same moment:

  | Thread | Agent | Task |
  |---|---|---|
  | `fix` | Umbral, `ollama/gpt-oss:20b` | fix the failing test |
  | `readme` | Umbral, `ollama/gpt-oss:20b` | update the README |
  | `rename` | OpenCode 1.18.33 over ACP (built-in manifest) | rename `Mean` to `Average` everywhere |

  OpenCode uses the same Ollama, set through `[acp.agents.config]`: provider
  `@ai-sdk/openai-compatible` at `http://127.0.0.1:11434/v1`.
- **Configuration:**
  - `[agents] max_concurrent_turns = 3`;
  - `[router] offline = true`;
  - `[otel] endpoint` pointing at a collector inside the test;
  - normal mode for every thread.
- **The user:** the test answers every approval. It approves once anything that is not `Network`
  and denies `Network`.
- **Versions:** Ollama 0.40.0 on the local GPU (`num_ctx = 16384`), Go 1.27.3, Linux. The daemon
  is built from the tree under test and runs with its own XDG directories.
- **What is asserted:** what the daemon did, not the quality of each agent's work.
  - The worktrees and the main copy.
  - Each diff stays inside its task's files. Allowed files:
    - `fix`: `stats.go`;
    - `readme`: `README.md`;
    - `rename`: `stats.go`, `report.go`, `stats_test.go`.
  - The merges, the `tool_calls` rows and the exported traces.
  - Each task's own check (`go test`, the README's names, the rename and `go build`) is logged, then
    run again on the main copy after the merges.

## Findings

1. **The hosted agent is not offline: it reaches npm and a model catalogue at start.** A sampler
   of OpenCode's TCP connections ran during run 2. It saw HTTPS connections to `registry.npmjs.org`
   (104.16.8.34 and 104.16.10.34) and to 104.20.32.17. They happened in the agent's first 80 s
   (11:47:39–11:49:00); nothing non-local followed. A 5.9 MB `models.json` appeared in its isolated
   cache two seconds after launch.
   - Cause: the isolated home Umbral gives the agent (REQ-ACP-009) has an empty cache. OpenCode
     therefore installs the `@ai-sdk/openai-compatible` provider from npm and fetches its model
     catalogue.
   - This is the agent's own traffic, which Art. 4's amendment and REQ-ACP-007 leave unobserved and
     disclose: Umbral recorded none of it, and the thread says `unobserved`. It is not a gap in
     mediation.
   - It does contradict PRD F2 §9's "so the whole scenario runs offline".
   - Possible remedy, which needs a delta: the manifest could set OpenCode's own switches
     (`OPENCODE_DISABLE_MODELS_FETCH`, `OPENCODE_DISABLE_AUTOUPDATE`, `OPENCODE_DISABLE_SHARE`,
     `OPENCODE_DISABLE_LSP_DOWNLOAD`, `OPENCODE_DISABLE_DEFAULT_PLUGINS`). The provider package
     would also have to be available without npm. This is left to the Tech Lead.
2. **The hosted agent knows the main copy and its sibling worktrees.** At start, OpenCode's log
   records a "project copy refresh". It lists the main working copy and all three threads'
   worktrees, which it found through git.
   - Its reads are unmediated by design (REQ-ACP-007's disclosure). A hosted agent can therefore
     read another thread's worktree.
   - Every write in this run stayed in its own worktree. Writes are mediated and bounded by the
     write root.
3. **A model calling a tool its agent does not have shows up as an `unmediated` `Exec` row.** See
   run 1. The record is accurate: the agent ran something Umbral did not decide, and here it was
   nothing. A reader of `tool_calls` cannot tell that from a real bypass without the arguments.
4. **The F2a turns are slow on one local GPU.** The threads took 24 to 35 minutes. Ollama serves
   the two local threads and OpenCode, whose prompt is large (the spike measured about 6 k tokens
   for "pong"). Each turn waits behind the others' model calls, so the scenario needs a timeout of
   tens of minutes.
