reason, and the second attempt did the same.

## What the runners found that this machine could not

`T-F0-26` was opened because "the gate is green" had meant the local gate for weeks. Getting
the GitHub gate green on both OSes took three rounds and exposed three more defects. Two of
them were in the daemon.

1. **`session.output` could precede the `session.subscribe` reply.** API §5.11 forbids this.
   The subscription exists before the snapshot, so a chunk queued in that window was written at
   once, racing the reply. Subscriptions now start held and are released after the reply is
   written. `TestSubscribeAnswersBeforeItStreams_REQ_TERM_004` was red 3/3 before the fix.
2. **Output published before `Server.Notify` was scheduled reached no one.** `Notify`
   subscribed to the bus inside its own goroutine. `Listen` now takes the subscription.
   `TestOutputPublishedBeforeTheDispatcherRunsIsDelivered_REQ_TERM_004` publishes before
   starting `Notify`, and was red before the move.
3. **The oversized-message test treated the daemon's hang-up as a failure.** It was the first
   run of that test on macOS. Pinning down what the daemon should do there became delta
   `2026-09-oversized-message` (`T-F0-27`). That delta found a real REQ-SEC-003 gap: before the
   handshake, invalid JSON and non-JSON-RPC lines were answered with a protocol error and left
   the connection open.

`TestOutputLatencyUnder5ms_REQ_TERM_006` is now serial. Measured beside the rest of its
package under `-race`, its p95 was measuring the runner's scheduler (p50 166 µs, p95 7–10 ms).
The benchmark in `task perf` remains REQ-TERM-006's gate.
