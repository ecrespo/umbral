## The finding worth carrying forward

`WithMaxScrollbackLines` **alone does nothing**. libghostty prunes on a byte budget and a
line budget together, and its default byte budget is small, so it wins. A terminal asked for
10,000 lines keeps 588. Both budgets together give 9,876, the documented page-granularity
approximation.

Nothing errors. Short test sessions pass. Users lose 94 % of their scrollback. `NewTerminal`
sets both, and the regression test calls that constructor rather than rebuilding the options,
so deleting either one fails the suite.

## Honest status

- **Not tested here, by design:** reflow on resize (REQ-TERM-002, T-F0-07), real PTY output
  (T-F0-05), macOS. Every case in this spike is a hand-written byte string on Linux.
- The bindings have **no tagged release** and their README disclaims API stability. The
  pseudo-version is pinned in `go.mod`, and this adapter is the only file in the repository
  that names a libghostty symbol, which is what the `Emulator` port is for.
- `task test` now takes about 8 seconds because of the scrollback test. It was 44 seconds
  before the test was rewritten to demonstrate the contrast at 3,000 lines rather than fill
  a tiny default budget 20,000 times.
- **CI has still never run on real GitHub**, and the Zig build step there is new and
  unexercised. It is the step most likely to fail on first push.
- The palette option exists but nothing calls it yet. T-F0-06 decides when to set it.
