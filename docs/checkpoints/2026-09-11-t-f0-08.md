## Two real bugs the tests found

Both were found by running actual shells under a PTY, and both now have a regression test
that was verified to fail without the fix.

**A phantom block at every session start.** bash's `DEBUG` trap fires for every element of
`PROMPT_COMMAND`, not just for user commands. With Starship installed, the first block of
every session recorded `starship_precmd` as its command. The fix is an arming flag set at
the end of the prompt hook, so the next command the trap sees is the one the user typed.

**Markers lost after the first command.** Starship and powerlevel10k reassign the prompt
variable on every prompt, so markers applied once are gone. The prompt is re-marked each
prompt, guarded by a marker check so the wrapping cannot stack.

A third, smaller one: `bash -i --init-file F` exits 2 with `--: invalid option`. bash's
usage is `bash [GNU long option] [option] ...`. `Bootstrap.Argv` assembles the list so a
caller cannot get the order wrong.

## Honest status

- **Tested under a PTY, not under the daemon.** `session.create` wiring the bootstrap into
  a real session is T-F0-05, and the OSC parser that turns these sequences into blocks is
  T-F0-09. Nothing here creates a block yet.
- **The prompt-framework test uses a fake rc, not Starship.** That is deliberate so it holds
  on a CI runner, but it means no test exercises powerlevel10k's instant prompt, which is
  the hardest real case.
- The bash arming flag assumes the hook is the **last** element of `PROMPT_COMMAND`.
  Something appended after it would run inside the armed window and be mistaken for a user
  command. Written in the script, untested.
- fish skips the configuration-preservation test by design, so that shell's rc handling is
  covered by inspection only.
- macOS is untested: the CI matrix runs the tests there, but `fish` is not installed on that
  runner and the test skips a missing shell rather than failing.
- PowerShell is REQ-BLK-008, deferred to F2 with Windows.
