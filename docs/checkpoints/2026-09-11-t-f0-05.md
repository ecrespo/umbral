## Shape

| Layer | Path | What it holds |
|---|---|---|
| domain | `internal/sessions/domain` | session, size, states, the input-lock rule; standard library only |
| ports | `internal/sessions/ports` | `Sessions`, `PTY`, `Emulator`, `Bootstrapper`, and the bus events |
| adapters | `.../adapters/{pty,ghostty,shellinteg}` | creack/pty, libghostty, the shell bootstrap |
| service | `internal/sessions` | the lifecycle, the lock and the state machine |
| wire | `internal/api/sessions.go`, `notify.go` | `session.*` methods and the §6 notifications |

Everything the service needs arrives as an injected factory, so the whole state machine is
testable without a PTY and libghostty stays in one directory. That is what contains the
Q-01 risk: bindings with no stable API, named in exactly one place.

## Two decisions worth knowing

**The linter is overruled twice, with reasons written in the code.** `noctx` and
`contextcheck` both want the shell bound to a request context. That would kill the session
when the call that created it returns, which is the exact opposite of REQ-TERM-003. Art. 1
allows a `//nolint` that says why, and these say why.

**Integration tests live in their own directory and their own arch-lint component.**
Wiring the real PTY, emulator and bootstrap together is a composition root's job. Excluding
every `_test.go` from the boundary rules would have been the one-line answer and would have
stopped enforcing Art. 3 in test code entirely.

## Honest status

- **Nothing streams output to clients yet.** The service publishes `session.output` on the
  bus and `api.Notify` deliberately drops it: per-session subscription, 4 ms / 32 KiB
  batching and the 8 MiB queue are T-F0-06. `session.subscribe` is not implemented.
- **No blocks.** The OSC parser that turns the T-F0-08 sequences into blocks is T-F0-09, so
  `integration` stays `pending` forever and REQ-BLK-003's five-second timer does not exist.
- REQ-TERM-005 promises the session's blocks survive its shell. There is no block writer
  yet, so what the test actually checks is that the session row is kept rather than deleted.
- **Exited sessions stay in memory.** They are kept so `session.list` and a late `Get` still
  report the exit code instead of answering NOT_FOUND for something that existed a moment
  ago. Nothing evicts them; a daemon running for weeks would accumulate them. Retention is
  T-F1-22.
- **Input written before the shell's line editor is ready can be lost.** An end-to-end
  script that types immediately after `session.create` saw a wrong exit code for that
  reason. With the shell settled, bash, zsh and fish all report the real code. Clients
  should subscribe and wait for a prompt before typing.
- `owner_thread_id` is carried through the API but never set: agent-owned PTYs arrive with
  T-F1-10.
- Notifications currently go to **every** authenticated connection. T-F0-06 narrows that to
  actual subscribers.
- macOS is untested for this module, and CI has still never run on real GitHub.
