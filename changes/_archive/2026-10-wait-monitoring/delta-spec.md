## Evidence

- **REQ-AUT-005**: a wait past the per-connection limit is `VALIDATION_ERROR` naming the limit; a report past its source's rate is `ok` and discarded; neither closes the connection or touches other sources.
- **REQ-AUT-006**: `wait.list` returns every active wait with id, owning connection, target, target states, age and the stalled mark.
- **REQ-AUT-007**: `wait.cancel` ends the wait with `CANCELLED` for whoever is waiting, without touching the turn, the process or the pane.
- **REQ-AUT-008**: no model event, tool call or output for the window (120 s local, 30 s remote, configurable) marks the turn `stalled`, notifies it and exposes it in `wait.list` and `thread.list`; it is never cancelled.
- **DD-017**: a stall is informational; exceeding a limit degrades that operation, never the connection.
- **API §6**: `thread.stalled {thread_id, turn_id, idle_ms, last_event}`.

## Decisions

1. **Every wait is registered.** `thread.wait`, the wait inside `thread.send` and `block.wait_output` are registered from the moment they are validated until they answer, with an id `wt_` + ULID (API §3), the connection that opened it, the target, `until` and the start time. The registry is the wait engine's (`internal/waits`); it is what `umbral_waits_active` counts.
2. **The limit is per connection and counts all three kinds.** A connection holding 32 open waits gets `VALIDATION_ERROR` for the 33rd — `"too many concurrent waits: the limit is 32 per connection"`, with `data.details: [{field: "timeout_ms", issue: "the connection already holds 32 waits"}]` (API §3's member; amended after the spec-guardian review, which found the draft naming `fields`), the one member every wait shares — before anything is subscribed, sent or read. For `thread.send` that means nothing is sent. The connection is not closed and the next wait succeeds once one ends.
3. **`wait.list`** params `{}`; result `{items: [{wait_id, connection_id, target, until, age_ms, stalled}]}`, oldest first, every connection's. A thread wait's `target` is `{thread_id}` and its `until` the states it waits for. An output wait's `target` is `{block_id}` when it observes a block and `{session_id}` when it watches a session's output; its `until` is `[]` and it carries `regex`, the pattern it waits for (additive). `stalled` is the target thread's stall mark (decision 6); an output wait's is `false`.
4. **`wait.cancel`** params `{wait_id}`; result `{}`. Any connection allowed to call it may cancel any wait — inventory and cancellation are the operator's tools, and a script that leaked waits is exactly the one that will not cancel them. The waiting request answers `CANCELLED`; the turn, the session and the pane are not touched, and for `thread.send` the message stays sent. An unknown or already ended `wait_id` is `NOT_FOUND`, and so is a second cancel: a cancelled wait leaves the inventory at once, before its request has answered. A cancelled `thread.send` answers `CANCELLED` without `turn_id` or `message_id`; the message is stored, so the client finds both with `thread.get` (amended after the spec-guardian review).
5. **Who.** `wait.list` and `wait.cancel` are advertised under `wait_admin`. §2's `cli` row gains `wait.list` and `wait.cancel` so `umb wait ls` and `umb wait cancel WAIT_ID` work; `thread.wait` stays interactive-only.
6. **Stall detection lives in the agent runtime.** A running turn's activity is its model events (text, reasoning, a tool call), the start and end of each tool call, an approval answered and output from its own pane. The runtime sees its own events as it publishes them, so none is lost to the bus's backpressure; output reaches it from `cmd/umbrald`, which follows `block.started` and `session.output` and tells the runtime when a session a thread owns writes. A watcher checks the running turns every second. A turn awaiting approval is waiting for the user, not stalled, and its clock restarts when it is answered; output from its pane while the user decides does not end the wait for the answer. A session belongs to the thread whose `block.started` last carried that thread's id, and `cmd/umbrald` reads `block.started` on a subscription of its own so an output flood cannot push it out (both amended after the spec-guardian review). When a turn has had no activity for its window the runtime marks it stalled, publishes `thread.stalled {thread_id, turn_id, idle_ms, last_event}` (`last_event` one of `turn_started`, `text`, `reasoning`, `tool_call`, `tool_result`, `output`, `approval`) and counts `umbral_waits_stalled_total`, once per stall. The next activity clears the mark without announcing it; a later silence is a new stall. The turn is never cancelled. The mark is not persisted: it describes a turn of this daemon run.
7. **Exposure.** §4's `Thread` gains `stalled: bool`, true while its running turn is marked (additive). `wait.list` reads the same mark.
8. **The window.** `[waits] stall_local_s` (120) and `[waits] stall_remote_s` (30), whole seconds from 5 to 3600; out of range stops the daemon naming the key; not live. A turn uses the local window when any candidate the router would try for its thread's model or class is a local provider (the router's `Local`, beside its `Window`), since a local model may legitimately take minutes; otherwise the remote one.
9. **The report rate.** `pane.report_state` and `pane.report_metadata` share one sliding window per `source`: at most 10 kept reports in any second. Validation and the pane's resolution run first, so a malformed report is still `VALIDATION_ERROR`, an unknown pane `NOT_FOUND` and an agent's pane `PERMISSION_DENIED`; then a report past the rate answers the method's normal result (`{}`) and writes, announces and resolves nothing, and `umbral_reports_rate_limited_total` counts it. A report is kept when it is written: a discarded, refused or stale report does not count against the window, so a source flooding at any speed keeps 10 a second (amended after the spec-guardian review, which found the draft silent on what "kept" and "validation" cover). `pane.release_state` is not a report and is not limited. Other sources are not affected.
