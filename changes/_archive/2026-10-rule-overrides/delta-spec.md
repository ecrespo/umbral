## Evidence

- **REQ-SEC-010**: load redaction rules and destructive patterns from `$XDG_CONFIG_HOME/umbral/rules/`, precedence over the built-in ones, invalid files ignored with a warning "without falling back to an empty rule set".
- **REQ-SEC-011**: opt-in fetch from the configured URL, verify, record in `egress_log`, apply only when every check passes, never override the local directory.
- **DD-016 Formats**: "a bundle is the exact bytes of a UTF-8 JSON document whose top-level `version` is a positive integer. The built-in rules are version 0."
- **Delta `2026-10-policy-explain`, decision 9**: the runtime and `policy.explain` must be handed the same `Policy`.

## Decisions

1. **One format for a local file and a bundle.** A UTF-8 JSON object `{"version"?, "redaction"?: [{"name", "pattern", "group"?}], "destructive"?: [{"name", "pattern"}]}`, decoded strictly: a document that is not an object (`null` included), an unknown member — a `group` on a destructive entry among them — trailing content, a negative `version`, a name outside `^[a-z0-9_]{1,64}$`, a name repeated within its list, a pattern that does not compile (Go RE2) or is over 4096 bytes, a `group` past the pattern's groups, or more than 256 entries in a list makes the whole file invalid. A local file's `version` is ignored; a bundle's is DD-016's.
2. **Precedence is by name, over one base.** The base is the built-in rules, or the active verified bundle (T-F1-30), which **replaces** them whole, as DD-016 and Tech §3 already say: a name the bundle leaves out is gone, so a bundle can retire a built-in rule that misfires. Each local file is layered on that base in lexical order of its name: an entry replaces the base's (or an earlier file's) entry of the same name in the same list and otherwise adds to it; the overriding entries run first. A local file can therefore replace a rule but not delete it, and the directory never leaves an empty set.
3. **What is read.** Regular files named `*.json` directly in the directory, each at most 1 MiB; anything else, links included, is skipped. A missing directory is no override. An invalid, unreadable or oversized file is logged as a warning naming the file and the reason ("over 1048576 bytes" for size) and is skipped whole; the other files still apply.
4. **When.** The directory is read once at start. Changes need a restart, as `models.toml` and `config.toml` do; no reload method is added.
5. **One shared set.** `cmd/umbrald` builds one active set and hands its `Policy` to both the agent runtime and `policy.explain`, and its redactor to the model gateway, MCP and every other redaction, each reading it at use. A bundle applied later (T-F1-30) changes the base under the local layer without restarting either.
6. **The fetch.** With `[update] rules_check = true` the daemon checks at start and every 24 h: a GET of `rules_url` and of `rules_url` + `.sig`, each recorded in `egress_log` **before** it is sent (provider `umbral-rules`, the URL's host, the URL's length as bytes sent and the SHA-256 of the URL), bodies capped at 4 MiB. A redirect is a request to a new host, so each hop is recorded the same way before it is followed; five redirects are followed, a sixth or a hop off `https` is not. Every request goes through redaction as Art. 4 requires, the way `fetch_url` does it: with `rules_check` on, a `rules_url` the active redactor would change — as written or with `.sig` appended — carries what looks like a secret and the daemon refuses to start. A redirect target is chosen by the server, carries nothing from this machine, and is recorded rather than redacted, as `fetch_url`'s hops are; GitHub's signed asset URLs would otherwise trip the entropy detector. A failure is logged by host and cause, never by URL, since a redirect target can hold short-lived signed parameters (Art. 7). A failed request, a status other than 200 or an oversized body is logged, offers nothing and is retried at the next check. With it off no request is made at all. `rules_url` must be `https://` with a host and no credentials, or the daemon refuses to start.
7. **Until T-F1-30 nothing fetched is applied.** A fetched bundle and its signature are handed to an updater that, in this build, logs that it cannot verify signatures and discards them (Art. 5). T-F1-30 replaces that updater with verification against the trust store.
8. **Where it lives.** The loader, the active set and the fetcher are an adapter: `internal/security/adapters/rules`, under the existing `security-adapters` component. The pure parsing and layering are in `internal/security/domain`. DD-016's `internal/security/rules/trustseed` and T-F1-30's **Files** move under `internal/security/adapters/rules/` accordingly.
9. **A local file may weaken a rule.** Replacing a built-in by name with a pattern that matches nothing keeps the set non-empty but disables that rule. That is accepted: the directory is the user's own, under their own account, and REQ-SEC-010 gives it precedence. "Never an empty set" means no file, valid or not, removes a rule; it does not promise a rule cannot be replaced.
10. **The egress row.** Data Model §2.12 gains `provider = 'umbral-rules'`, whose payload is the request URL: `host` is the URL's, `bytes` its length and `payload_sha256` its digest, for the configured URL, its `.sig` and every redirect hop.
