# Contributing to Umbral

Thanks for your interest. Umbral is built with **Spec-Driven Development (SDD)**: the specification
is the primary artifact and the code implements it. This document explains the flow; `AGENTS.md`
summarizes the same for coding agents.

## Before you start

1. Read [`specs/constitution.md`](specs/constitution.md). Its 9 articles are not negotiated per PR.
2. Find the task in `specs/tasks/` or in the issues labeled `type:task`.
3. If your idea is not specified yet:
   - for new work, open a **Feature** issue;
   - if it changes already-specified behavior, open a **Delta Spec** in `changes/`.

## Per-task flow

| Step | What to do |
|---|---|
| 1. Branch | `feat/T-F0-03-api-jsonrpc`, `fix/<issue>-<slug>`, `spec/<slug>` for spec changes |
| 2. Tests first | every test cites its REQ in the name: `TestHelloRejectsBadToken_REQ_SEC_003` |
| 3. Implementation | respecting the Tech Design §5.2 boundaries (`task arch` checks them) |
| 4. Local gate | `task lint && task arch && task test` green (available from T-F0-01) |
| 5. Spec up to date | mark the task `[x] YYYY-MM-DD` in its tasks file; if the spec was wrong, open a Delta **before** continuing |
| 6. PR | use the template; link `Closes #<issue>` and list the REQs covered |

## Commits

[Conventional Commits](https://www.conventionalcommits.org/), with the task and the REQs in the
message footer:

```
feat(api): reject connections without valid token

Refs: T-F0-03
REQ: REQ-SEC-003, REQ-SEC-007
```

Types: `feat`, `fix`, `test`, `refactor`, `docs`, `spec` (changes in `specs/` or `changes/`),
`build`, `ci`, `chore`.

## Language

Everything in this repository is written in **English**: specifications, documentation, code,
comments, identifiers, commit messages, log messages and agent configuration.

## Go style

- Formatting with `gofumpt`; linting with `golangci-lint` (includes `gosec`).
- Domain errors as sentinels checked with `errors.Is`; never `panic` in domain code.
- `context.Context` as the first parameter of every I/O or cancellable operation.
- No mutable global state except in `cmd/*`.
- Timestamps in UTC epoch ms, costs in micro-USD `int64` and prefixed ULID IDs (Constitution Art. 6).

## Review

A PR is merged when:
- CI is green;
- it follows the template;
- it touches only the files its task declares (or justifies otherwise);
- `specs/` reflects the new behavior.

PRs generated by agents follow the same rules and always go through human review.
